Pipecat #5760: function call timeouts were cancelled by progress updates

Pipecat is a framework for realtime voice agents. Pull request #5760 keeps a function call timeout armed when a tool reports an intermediate result. It was merged on 15 Sep 2026.

What was broken

An intermediate result, FunctionCallResultProperties with is_final=False, cancelled both the per tool timeout_secs and the global function_call_timeout_secs. A tool that reported progress disarmed its own deadline. If that tool then hung, the timeout no longer fired. The pull request closes issue #5481. It also says an earlier attempt, #5491, was closed without review, and that this change reopens that approach on current main.

What changed

Only a final result clears the deadline. The deadline covers the handler's whole execution. A progress update does not clear it and does not restart it. The docs on register_function and register_direct_function say this explicitly. The code is in src/pipecat/services/llm_service.py, with tests in tests/test_llm_service.py and a changelog note in changelog/5760.fixed.md. The new test checks that an intermediate update does not disarm the deadline. A control test checks that a hanging async tool with no update still times out.

Genkit #6346: base64 embeddings from the OpenAI plugin failed validation

Genkit is a framework for building AI applications. Pull request #6346 is on genkit-ai/genkit, in the Python OpenAI plugin. It was merged on 23 Sep 2026. It fixes issue #6317.

What was broken

The embedder forwarded encodingFormat: 'base64' to embeddings.create(). The pull request says that passing base64 explicitly is what turns off the SDK's own decoding. The SDK still sends encoding_format=base64 when the parameter is omitted, and it decodes the response to floats only in that case. With the parameter forwarded, embedding validation failed. The pull request's repro used a mock transport, not a live provider. Before the change, that repro failed with 1 validation error for Embedding.

What changed

The embedder no longer forwards base64. float is still forwarded, because that is a different request. In the same mock repro, the transport returned the vector 0.1, negative 0.25, 0.5 as a base64 32 bit float, and the decoded result was [0.10000000149011612, -0.25, 0.5]. The change is in py/packages/genkit-openai/src/genkit_openai/openai_plugin.py, with tests in py/packages/genkit-openai/tests/openai_plugin_test.py. One test checks that a base64 request omits the parameter. Another checks that a float request still sends encoding_format='float'.

Strands Agents harness SDK #4313: AgentResult.to_dict raised TypeError on bytes

Strands Agents publishes the harness SDK. Pull request #4313 makes AgentResult.to_dict() safe for json.dumps when a message contains raw bytes. It was merged on 14 Sep 2026. It fixes issue #4167.

What was broken

AgentResult.to_dict() promised a dictionary that JSON can serialize, but it passed message through unchanged. The pull request says Bedrock Converse can put raw bytes in message content, for example reasoningContent.redactedContent. json.dumps(result.to_dict()) then raised TypeError. The pull request also says downstream runtimes that fall back to str(obj) then broke consumers.

What changed

to_dict now passes message through encode_bytes_values, the same helper session persistence uses. from_dict passes it through decode_bytes_values, so a round trip restores the original bytes. The code is in strands-py/src/strands/agent/agent_result.py. A regression test in strands-py/tests/strands/agent/test_agent_result.py puts bytes in redactedContent, serializes with json.dumps, and checks that from_dict restores those bytes. The pull request reports that this test file passed 30 tests, including that regression. I am reporting the pull request's own test note, not a run I repeated here.

Open

LiveKit Agents #7186: the EndCallTool wait is still open, not merged

LiveKit Agents is a framework for realtime voice agents. Pull request #7186 is open. It has not been merged. I checked the pull request on 17 Nov 2026 and it was still open.

What the pull request says is broken

_delayed_session_shutdown waits for speech_created with asyncio.wait_for and a timeout of 5.0 seconds, then awaits the speech handle with no timeout. The pull request says that if that handle never completes, the finally block never runs, ctx.session.shutdown() is skipped, and room cleanup including delete_room never happens. It says SIP can stay up. It frames the change as the timeout asymmetry only, and says it is not a fix for Gemini instruction following. It references issue #5096.

What the pull request changes

The speech handle await is wrapped in the same TOOL_REPLY_TIMEOUT. The existing warning and shutdown path stay. The pull request names the test test_delayed_session_shutdown_times_out_when_speech_handle_hangs and says that test hangs on main and passes with the change. It also says the tests cover speech_created never firing, and a handle that completes normally. The pull request was opened on 9 Sep 2026. Until it is merged, this is an open proposal, not a change in LiveKit Agents.
