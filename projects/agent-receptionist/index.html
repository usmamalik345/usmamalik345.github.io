Agent Receptionist, one receptionist for many businesses

It ships with 22 sample tenants: 11 hotels and 11 dental clinics. Twenty are fictional. Two, Erth Abu Dhabi and MM Dental Care, were built from public facts, and unpublished facts are left null.

Source on GitHub Live demo: hotel Live demo: dental

The problem

A hotel desk and a dental practice both need someone to answer hours, prices, policies and bookings, and to hand a caller to a person when the question is not one of those. They do not need a separate product, and they must not share a diary, a phone number or a rate card. If the model is asked to invent a price that was never published, the caller hears a fact the business did not state.

Agent Receptionist is that shared product. The tenant comes from the call, not from anything the caller can type. A missing fact stays missing.

How a turn is handled

Caller text or speech hits a per-tenant rate limit, then an injection screen. The screen is rules, and it runs before any tool. A blocked turn goes to the guard. A turn that passes goes to the triage agent, also rules.

Triage hands off, with a validated hand-off message, to one of three agents:

  • FAQ agent. Tools are get_hours, get_prices, get_policy and search_knowledge. An open question goes to the response agent, which is the only language-model step: cache, then a small model, then a filler line and a hand-off.
  • Booking agent. Hotel tools check room availability and book a room. Dental tools check appointment slots and book an appointment. The write tools run only with a confirmed yes.
  • Human hand-off. The tool is handoff_to_human.

The guard agent then checks grounding, personal data and cross-tenant leaks. After the guard, the reply is turned into sentences and spoken. The hotel booking flow collects dates, guests, room type, name and phone, then reads it back. The dental flow collects treatment, location, day and time, name and phone, then reads it back. Each vertical has its own tools.

The injection screen is the same kind of early check I describe in the prompt injection defence note. BleedStop is a separate cost and security guard, with its own measurements.

Twenty-two sample tenants, and two that use public facts

The repository ships with 22 sample tenants, 11 hotels and 11 dental clinics. Twenty are fictional. Their names, addresses and phone numbers sit in the 555-01xx and Ofcom drama ranges.

The other two were built from public facts. Erth Abu Dhabi uses facts from erth.ae. MM Dental Care uses facts from mmdentalcare.co.uk. Where a fact is not published, the field is null and the agent says the team will confirm it. Erth room rates are one of those unpublished facts. The MM Dental Care check-up price is another. Nothing is invented to fill the gap.

The live demos are the hotel console and the dental console. On Vercel the console runs the orchestrator in the browser with the deterministic mock responder, so no API key reaches the browser. Real model answers need the API server.

Tenant isolation

Tools take the tenant from the call context, never from arguments, and any tenant_id argument is rejected. The booking store, the response cache key and the rate-limit buckets are all keyed by tenant. The cache key is the question, the tenant and the policy version. The guard blocks any reply that names another tenant's business or speaks its phone number. Tests cover all 22 tenants.

On Postgres, each request runs in a transaction with app.tenant_id set, and row-level security hides other tenants' rows, so a query that forgets the filter still cannot read or write across tenants. The app has to connect as a normal role, because superusers bypass row-level security. Without DATABASE_URL the in-memory store is used, which is what tests, evals and the static Vercel demo use. SQLite is the zero-setup local file.

Writes need a confirmed yes

book_room and book_appointment run only with the confirmation id issued when the caller says yes to the read-back. A model reply is not enough to create the booking. The 25 Nov 2026 release gate recorded 0 writes without confirmation.

The database backs that up for the stored rows. A partial unique index on tenant, location, date and time means a slot is not double-booked, including under races. Room nights have a primary key of tenant, room type, night and unit, so a room is not oversold under concurrent bookings. Call logs do not store the caller's words.

The fast path, and when the model is called

Hours, prices, policies, bookings and hand-offs are answered by tools and templates. The language model is called only for open FAQ questions, and it is grounded on the tenant's own knowledge passages.

On the 25 Nov 2026 platform eval, that was 60 of 670 turns.

Results from dated runs

On 25 Nov 2026, the platform release gate, run in-process with the mock responder, passed 270 of 270 cases and 670 of 670 turns. Hotel was 140 of 140 and dental was 130 of 130. The 15 categories include booking, booking change, side question, hand-off, injection, exfiltration, cross-tenant, tool error and emergency. There were 0 safety failures and 0 writes without confirmation. The gate requires at least 95 percent overall and 100 percent on the safety categories.

On 25 Nov 2026, from 01:25 to 01:30 AM PKT, the same 270 cases and 670 turns passed against Groq's free-plan model openai/gpt-oss-20b, on a cloud box, text only. That run had 0 safety failures, 1 guard block that caught a cross-tenant leak, 60 model turns, 17,681 tokens (about 295 per answer), an FAQ-agent p50 of 0.23 ms and p95 of 401 ms, and a cost of $0.

On 24 Nov 2026, from 12:30 to 12:47 PM PKT, the legacy pipeline on the same Groq free-plan model replayed 100 of 100 calls and 138 of 138 turns, with 25 of 25 grounded, 0 HTTP 429s and a cost of $0.

On 25 Nov 2026, npm test reported 147 passing tests and 1 skipped. The skipped test is the Postgres row-level security test, which needs PG_TEST_URL. With that variable set on a local Postgres 17, the suite was 153 of 153. The dental eval gate the same day, on the mock responder, was 30 of 30.

On 25 Nov 2026 at 01:55 PKT, one Node process served the HTTP API on localhost with the mock model. The concurrency run sent 10, 20 and 50 simultaneous 9-turn calls, described in the report as across all 20 tenants. It recorded 0 errors, 0 timeouts, 0 wrong-tenant answers or bookings, and 0 double-booked slots. Turn latency was p50 6.0, 9.1 and 16.1 ms, and p95 38, 11 and 72 ms, at about 455, 925 and 1,080 turns per second.

MAX_TOKENS_PER_CALL of 2,500 and TOKEN_RESERVE_PER_ANSWER of 550 come from measured token use: an average of 304 tokens and a maximum of 544 tokens per model answer, across a replay of n=25 and a probe of n=90. CALLER_SILENCE_MS of 7,000 is a design default and was not measured. The per-agent table for the release gate is written to metrics/platform-eval.md by the command. That file is generated and is not committed.

Not measured

  • Speech recognition (STT) was not measured.
  • Speech synthesis (TTS) was not measured.
  • Real time-to-first-audio was not measured.
  • Phone-line latency was not measured.
  • Speech quality, STT accuracy, TTS latency and time-to-first-audio were not measured.

The latencies above are in-process. The FAQ p95 includes the Groq call. Timings in the browser console are in-browser and are not phone latency. CALLER_SILENCE_MS of 7,000 was not measured. It is a design default.

The Docker image has not been built

The image has not been built yet: Docker was not available on the build box. docker-compose.yml itself was not run for the same reason. The setup, the init role script, the migrations, row-level security and the API in production mode were run against a local Postgres 17. Building and scanning the Docker image is still an open item. The image, when it is built, is specified to run as a non-root user with a health check on /healthz.

What this shows if you need a voice or chat receptionist

  • Many businesses can share one receptionist without sharing bookings, cache entries or phone numbers. The tenant is taken from the call, and a tenant_id argument is rejected.
  • Most turns never call a model. On the dated eval, the model ran for 60 of 670 turns, and only for open questions grounded on that tenant's passages.
  • A write waits for a confirmed yes. The release gate's count of writes without confirmation was 0.
  • Missing public facts stay null. Erth room rates and the MM Dental Care check-up price are examples.
  • The limits are written down: speech, phone latency and a built Docker image are not in these results.
